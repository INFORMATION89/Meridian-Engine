# Week 1 (Nov 22–28, 2026)

Meridian's product and engineering foundation is now documented: an independent, local-first weather engine with Solstice as its first consumer—not a dependency. The strict Level 2 product goal remains improving existing forecasts through source evaluation, blending, regional adaptation, uncertainty, and reproducible verification. Privacy, clean-room research, and AI-assisted development rules remain part of the project baseline.

## Platform foundation

M0.1's Kotlin Multiplatform platform proof was merged in PR #15. Its five-job CI matrix passed for the tested Android x86_64 emulator, iOS ARM64 simulator with a Swift consumer, JVM consumers on Windows, macOS, and Linux, and dependency/license checks.

The owner-approved production baseline is recorded in ADR-0003 and was merged to `main` through PR #19: Kotlin Multiplatform for the shared core, Ktor for networking, optional SQLDelight/SQLite behind a storage boundary, JVM-first desktop distribution, and a Swift-friendly iOS facade. Rust/UniFFI and native desktop ABIs remain deferred unless real consumer requirements justify them.

The M0.1 result is a bounded CI-only platform proof, not a claim that all devices and native integrations are supported. Android ARM64 runtime, physical mobile devices, native desktop ABIs, and final mobile release-package notice inclusion remain unverified. No meteorological forecast accuracy has been validated yet.

## Current focus — M0.2

PR #20 contains an experimental, app-agnostic contract proof under `io.meridian.contractspike`. It models coordinate-based requests, independent per-feature outcomes, source provenance, issue/fetch/valid/expiry times, typed problems, cancellation, and optional in-memory caching. Its fixture keeps measured air temperature separate from apparent temperature and demonstrates that one unavailable feature does not erase a successful one.

The proof is exercised by standalone desktop, Android, and Swift consumers without a Solstice dependency. It uses only fake data: no live provider, production weather algorithm, production database schema, hosted service, telemetry, or UI has been introduced. The code and API shapes remain experimental and are not approved public contracts.

The latest recorded full green M0.2 code matrix is [CI #266](https://github.com/INFORMATION89/Meridian-Engine/actions/runs/45958135944), which passed all five jobs for code head `b32f5abbf67cfd62d6a7ed410caa3448d303e5cf`: Linux and Windows desktop, Android host and x86_64 emulator, Apple/iOS with the native Swift consumer, and dependency/license audit. Two later commits reconciled documentation and evidence. Subsequent branch-history reconciliation preserved the same file contents while bringing the PR up to date with `main`; a separate run on that reconciled head still needs a completed result before merge.

Important M0.2 limitations remain explicit: the prototype currently represents one valid time and one provenance record for an entire feature payload. A stable Level 2 contract needs sample-level valid times and provenance for time series, multi-source blending, and transformations. The production cache identity must also include every request, source, and configuration dimension that can change a result. Neither issue is solved by the current spike.

## Swift cancellation investigation

PR #21 recorded the limitation of the direct generated Swift completion-handler bridge: it invoked Kotlin suspend functions but did not propagate Swift `Task` cancellation. The PR is now closed as a diagnostic experiment. PR #24 tested KMP-NativeCoroutines 1.0.7 with an async-only Swift package and an unannotated control method. [CI #251, attempt 3](https://github.com/INFORMATION89/Meridian-Engine/actions/runs/45916840825) passed all five jobs; native Swift XCTest passed 12/12 tests, including `testNativeCoroutinesPropagatesSwiftTaskCancellation` (0.076 s). Android passed host tests and eight x86_64 emulator instrumentation tests.

The self-contained JVM desktop images launched without an installed system Java: 183 MiB on Linux, 169.7 MiB on Windows, and 184 MiB on macOS. The iOS simulator XCFramework measured 108 MiB. The upstream `v1.0.7` source tag's `LICENSE.txt` is MIT; the plugin and marker coordinates still lack license identifiers in published SBOM metadata. This verifies the tested cancellation path and bounded packaging proof, but PR #24 remains a draft pending review of whether the dependency belongs in the production integration boundary. It does not establish release-ready mobile packages.

## AI-assisted engineering

The merged AI cost policy clarifies that a balanced ChatGPT coding model and Claude Sonnet are interchangeable options for standard engineering. Opus is an optional escalation or independent review for work where deeper reasoning can materially reduce risk; it is not a prerequisite for starting work or an automatic authorization for extra spend.
