# Week 1 (Nov 22–28, 2026)

Meridian's product and engineering foundation is now documented: an independent, local-first weather engine with Solstice as its first consumer—not a dependency. The project direction preserves the Level 2 goal of improving existing forecasts through source evaluation, blending, regional adaptation, uncertainty, and verification. Privacy, AI-assisted development, and clean-room research rules are also established.

## Platform foundation

M0.1's KMP platform proof was merged in PR #15. Its final CI matrix passed all five jobs, exercising the Android x86_64 emulator, iOS ARM64 simulator with a Swift consumer, and JVM consumers on Windows, macOS, and Linux, plus dependency/license checks.

The owner approved Kotlin Multiplatform for the shared core, Ktor for networking, optional SQLDelight/SQLite behind a storage boundary, JVM-first desktop distribution, and a Swift-friendly iOS facade. The written ADR and documentation reconciliation are in open PR #19. Rust/UniFFI and native desktop ABIs are deferred unless real consumer requirements justify them.

The M0.1 result is a bounded CI-only platform proof, not a claim that all devices and native integrations are supported. Android ARM64 runtime, physical mobile devices, native desktop ABIs, and final mobile release-package notice inclusion remain unverified. No meteorological forecast accuracy has been validated yet.

## Current focus — M0.2

PR #20 proposes a consumer-neutral public API and optional storage contract. It now includes concrete recommended defaults for request lifecycle, partial results, cancellation, freshness, persistence, retention, Swift interoperability, and versioning. These are still proposals: the final public API, storage guarantees, and compatibility policy have not been approved.

PR #21 adds native Swift async/await and task-cancellation tests against the existing Kotlin suspend probe. As of this update on Nov 26, four of its five CI jobs have passed; the Apple/iOS job is still running. This test does not change production API code.

The weekly Wiki publisher was added in PR #18 and merged. Its first run stopped because the repository secret `WIKI_TOKEN` was not configured; publishing has not yet been verified.

## Next
