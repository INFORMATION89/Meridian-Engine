# Week 1 (Nov 22–28, 2026)

Meridian's product and engineering foundation is now documented: an independent, local-first weather engine with Solstice as its first consumer—not a dependency. The project preserves the Level 2 goal of improving existing forecasts through source evaluation, blending, regional adaptation, uncertainty, and verification. Privacy, AI-assisted development, and clean-room research rules are also established.

## Platform foundation

M0.1's Kotlin Multiplatform platform proof was merged in PR #15. Its five-job CI matrix passed for the tested Android x86_64 emulator, iOS ARM64 simulator with a Swift consumer, JVM consumers on Windows, macOS, and Linux, and dependency/license checks.

The owner approved Kotlin Multiplatform for the shared core, Ktor for networking, optional SQLDelight/SQLite behind a storage boundary, JVM-first desktop distribution, and a Swift-friendly iOS facade. The written ADR and documentation reconciliation are in open PR #19. Rust/UniFFI and native desktop ABIs remain deferred unless real consumer requirements justify them.

The M0.1 result is a bounded CI-only platform proof, not a claim that all devices and native integrations are supported. Android ARM64 runtime, physical mobile devices, native desktop ABIs, and final mobile release-package notice inclusion remain unverified. No meteorological forecast accuracy has been validated yet.

## Current focus — M0.2

PR #20 now contains an experimental, app-agnostic contract proof under `io.meridian.contractspike`. It models coordinate-based requests, independent per-feature outcomes, source provenance, explicit issue/fetch/valid/expiry times, typed problems, cancellation, and optional in-memory caching. Its fixture keeps measured air temperature and apparent temperature separate, and demonstrates that one unavailable feature does not erase a successful one.

The proof is exercised by standalone desktop, Android, and Swift consumers without a Solstice dependency. It uses only fake data: no live provider, production weather algorithm, production database schema, hosted service, telemetry, or UI has been introduced. The code and API shapes remain experimental and are not approved public contracts.

The latest completed M0.2 matrix (#236) passed Linux and Windows desktop, the dependency/license audit, and Apple/iOS including the new Swift M0.2 consumer test. Android host-side tests and the new M0.2 contract consumer on the x86_64 emulator also passed. One pre-existing Android probe test (`mapsFixtureTimeoutAndTransportFailure`) failed while asserting a 50 ms timeout classification. I updated its helper to report the actual error code instead of returning an opaque false; the new diagnostic run [#240](https://github.com/INFORMATION89/Meridian-Engine/actions/runs/45911449431) is validating the corrected test helper.

The prototype is deliberately marked with Kotlin `@RequiresOptIn` so production callers cannot use its types without acknowledging the experimental status. Its time model now separates observation time from forecast issue time and computes forecast lead as issue-to-valid time. These are proof semantics, not approved public contract decisions.

PR #21's direct Swift async/cancellation proof completed with 11 of 12 native Swift tests passing. Direct `async/await` invocation works, but cancelling a Swift `Task` did not cancel the Kotlin suspend coroutine within the five-second test timeout. Linux, Windows, and Android platform jobs passed. Its dependency audit separately encountered Maven Central HTTP 429 rate limiting.

PR #24 tests KMP-NativeCoroutines 1.0.7 as a possible cancellation bridge. The first attempt exposed missing Gradle verification entries. I recovered Gradle-generated SHA-256 values for the eleven new plugin/module components and added them without weakening strict dependency verification. A copied checksum for the annotations JVM module was then corrected from the audit artifact. The refreshed full matrix is queued in [CI #239](https://github.com/INFORMATION89/Meridian-Engine/actions/runs/45911632799).
